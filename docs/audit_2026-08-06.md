## 0. Verdict

**Status: NOT RELEASABLE. NOT GOVERNANCE-CONFORMANT.**

The repository is an architecturally coherent **scaffold** whose headline capability — *self-critique with automated backtracking* — is **non-functional in every shipped code path**, and whose persistence layer contains a **confirmed arbitrary-file-write vulnerability**.

Three findings are load-bearing and were reproduced, not inferred:

1. **Path traversal (CRITICAL/security).** A caller-controlled `cycle_id` wrote a checkpoint file to `D:\Projects\ESCAPED\` — outside the configured storage directory *and* outside the workspace.
2. **The critique gate can never fail (CRITICAL/functional).** Every shipped execution handler hardcodes `success=True`, so the score is always `1.0` and backtracking is unreachable outside of tests.
3. **Backtracking cannot learn (CRITICAL/design).** When forced to fail, the cycle retried the *identical* plan three times and the rollback *destroyed* the critique feedback that would have informed a new plan.

Against the Permanent Active Directives, **Law 9 (auditable ledger) and Law 10 (operational boundaries) are actively violated**, not merely unimplemented.

The good news: none of this is architectural dead-end territory. The tier/phase decomposition is sound. The defects are concentrated in four files and are all fixable.

## 2. Critical Defects

### C-1 — Path traversal / arbitrary file write ⛔ CRITICAL

**File:** [orrery/core/state.py](../orrery/core/state.py) — `_save_to_disk`, `_load_from_disk`, `get_checkpoint`
**CWE-22 / OWASP A01**

`cycle_id` and `checkpoint_id` are interpolated directly into filesystem paths with no validation:

```python
cycle_dir = self.storage_dir / checkpoint.cycle_id     # attacker-controlled
target_file = cycle_dir / f"{checkpoint_id}.json"      # attacker-controlled
```

**Reproduced:** setting `ctx.cycle_id = "../../ESCAPED"` wrote to `D:\Projects\ESCAPED\<uuid>.json`. Both fields are ordinary mutable Pydantic `str` fields on `StateContext`, settable by any caller, restorable from any checkpoint file, and — once adapters are real — reachable from LLM-generated content.

**Fix:** validate both as UUIDv4 (`uuid.UUID(value, version=4)`) at the `types.py` model boundary, and additionally assert `resolved_path.is_relative_to(self.storage_dir.resolve())` before every read/write.

### C-2 — Checkpoint ledger is unsigned and mutable ⛔ CRITICAL — ✅ RESOLVED (Gate 2)

**File:** [orrery/core/state.py](../orrery/core/state.py)

Checkpoints are plaintext JSON with no hash chain, no signature, no integrity field, and no restrictive file mode. Anyone with write access to `.checkpoints/` can rewrite an agent's goal, planned actions, or execution history, and `restore_checkpoint` will load it as authoritative truth. `Checkpoint.state_data` is `Dict[str, Any]` — an unvalidated container that is then `model_validate`d back into live agent state.

This is the direct negation of Law 9 and Covenant §2.3. It is also, per the landscape report, the **exact feature that would differentiate this project from LangGraph**. Fixing it converts the top liability into the top asset.

**Resolution.** [integrity.py](../orrery/core/integrity.py) seals every checkpoint with a SHA-256
digest over its canonical JSON plus the digest of its predecessor, forming a per-cycle hash chain.
`_load_from_disk` verifies before returning, so an edited checkpoint is **refused rather than
restored**. `verify_chain(cycle_id)` walks the whole chain and reports both digest mismatches and
broken links. `0o600` was already applied in Gate 0. Optional HMAC-SHA256 signing is available via
`ORRERY_CHECKPOINT_KEY`, and `integrity.require_signature` makes an unsigned checkpoint raise
`IntegrityError`.

**Residual risk, stated plainly.** Signing is **off by default**, and an unsigned hash chain stops
corruption and casual editing but not an attacker with write access, who can simply recompute the
chain. Even when enabled, a shared symmetric key proves custody, not authorship. Asymmetric
per-operator signing is not implemented; tracked as `LAW9-SIGN` (PARTIAL) in
[GOVERNANCE.md](../GOVERNANCE.md).

### C-3 — The self-critique gate is unreachable ⛔ CRITICAL — ✅ RESOLVED (Gate 1)

**Files:** [dispatcher.py](../orrery/core/dispatcher.py), [meta.py](../orrery/cycles/meta.py), [macro.py](../orrery/cycles/macro.py), [meso.py](../orrery/cycles/meso.py), [micro.py](../orrery/cycles/micro.py), all three adapters

`SelfCritiqueEngine.evaluate` computes `success_ratio` purely from `receipt.success`. Every producer of receipts in the codebase hardcodes `success=True`. Therefore `score == 1.0` always, `passed` is always `True`, and the `θ=0.70` threshold, the backtracking machinery, and the `FAILED` status are **dead code in production paths**.

The only place backtracking executes is `test_backtracking_trigger_on_failed_reflection`, which injects a bespoke failing handler. **The framework's marquee feature is exercised exclusively by a test fixture.**

**Resolution.** Every hardcoded `success=True` was deleted. Actions now route through an adapter
registry on `CycleDispatcher`; an action whose `target_adapter` is unregistered yields a receipt with
`success=False` and an explicit error, and an adapter that raises is converted into a failed receipt
rather than propagating. An unwired framework therefore reports `FAILED`, not success. Covered by
`test_unregistered_adapter_fails_rather_than_reporting_success` and
`test_adapter_exception_becomes_failed_receipt`.

### C-4 — Backtracking destroys the feedback it exists to use ⛔ CRITICAL — ✅ RESOLVED (Gate 1)

**File:** [orrery/core/state.py](../orrery/core/state.py) — `backtrack()`

Reproduced with a persistently-failing execution handler:

```
status: FAILED | steps: 7 | backtracks: 3
distinct plans tried: ['default_execute_goal']
critique recs seen by planner: 1
```

Three observations, each serious:

- **Identical retry.** All three attempts ran the same single plan. `backtrack()` restores the pre-PLANNING snapshot and re-runs the same deterministic planner with the same inputs. It cannot produce a different outcome.
- **Feedback erased.** `CritiqueResult.recommendations` — the *entire point* of the reflection phase — lives on `context.critiques`, which is **rolled back and discarded**. Only 1 critique survived 3 failures. The planner never learns why it failed.
- **Ledger regression.** `step_count` is restored from the snapshot, so the step counter moves *backwards*. The audit trail is rewritten by rollback, which is precisely what Law 9's append-only requirement forbids.

**Fix:** carry a monotonic, rollback-immune `attempt_log` / `lessons` field forward across backtracks, and feed `recommendations` into the next PLANNING pass. Keep the event ledger append-only and separate from the rewindable state.

**Resolution.** `StateContext` gained rollback-immune `lessons` and `attempt_log` fields.
`CheckpointManager.backtrack` now carries both forward and takes `max(restored, current)` on
`step_count`, so the counter never regresses. The default planner reads `context.lessons` and emits a
distinct plan per attempt. Re-running the same reproduction:

```
status: FAILED | steps: 13 | backtracks: 3
distinct plans tried: ['default_execute_goal', 'default_execute_goal_attempt_2',
                       'default_execute_goal_attempt_3', 'default_execute_goal_attempt_4']
attempts recorded: 4
lessons retained: 4
planner saw lessons on final attempt: True
```

Covered by `test_backtracking_varies_the_plan_and_retains_lessons` and
`test_step_count_never_regresses_across_backtracking`. The remaining half of the fix — an append-only
event ledger held separately from rewindable state — was delivered in Gate 2 as
[ledger.py](../orrery/core/ledger.py), verified by `test_ledger_survives_backtracking`.

### C-5 — Unbounded, unauthorized sub-agent spawning ⛔ CRITICAL (Law 10) — ✅ RESOLVED (Gate 2)

**File:** [orrery/cycles/base.py](../orrery/cycles/base.py) — `delegate_to_child`

No depth limit, no authorization check, no delegation budget, no cycle detection, no tier-ordering enforcement. Nothing prevents a `MicroCycle` from delegating to a `MetaCycle` and recursing until stack exhaustion. `MetaCycle.execute()` unconditionally instantiates `MacroCycle()` on every run, which chains to Meso, which chains to Micro — a hardcoded cascade with no conditionality and no budget.

Law 10 forbids exactly this. It is also a straightforward local DoS.

**Resolution.** Every delegation is now authorized before it runs by
[delegation.py](../orrery/core/delegation.py), against five policies: depth (`DEL-001`), per-parent
fan-out (`DEL-002`), tree population (`DEL-003`), ancestry loops (`DEL-004`), and tier ordering
(`DEL-005`). Parent and children share one `DelegationBudget`, so the caps bound the tree rather than
each cycle independently, and `spawn_child` propagates settings and policy so governance is not reset
one tier down. A refusal produces a failed receipt and a lesson rather than an exception, so the
parent's own reflection handles it, and every decision — permitted or refused — is written to the
ledger with its deciding policy ID.

A `MicroCycle` delegating to a `MetaCycle` is refused by `DEL-005`; unbounded recursion is refused by
`DEL-001`. Covered by `tests/test_delegation.py` (12 cases).

**Residual risk.** Authorization is *policy-based*, not *cryptographic*. There is no signed approval
token from Governance and no attestation that the running configuration is the approved one; tracked
as `LAW10-APPROVAL` (NOT ENFORCED) in [GOVERNANCE.md](../GOVERNANCE.md).

## 6. What Is Actually Good

Stated plainly, because a credible audit is not only a list of failures:

- The **phase/tier decomposition is sound** and maps cleanly onto real cognitive-architecture literature. The abstraction is not confused.
- **Pydantic typed contracts throughout** — `types.py` is clean, well-factored, and gives you free validation and serialization. This is the strongest file in the repo.
- **Async-first** handler signatures mean real I/O can be introduced without redesign.
- Handler registration via `register_handler` is a **genuinely good extension seam** — the failing-handler test proves it works.
- `SelfCritiqueEngine` is correctly decoupled from the dispatcher and cleanly testable.
- The **defects are concentrated in four files** (`state.py`, `dispatcher.py`, `cycles/base.py`, the tier `execute()` methods). This is a tractable remediation, not a rewrite.

## 7. Remediation Plan

**Gate 0 — Stop the bleeding (before any commit is pushed publicly)**

10. ✅ Fix C-5: authorization, depth cap, delegation budget, ancestry-loop and tier-ordering enforcement on `delegate_to_child`.

## 9. Auditor's Note

Per the Quaternary Directive's instruction to act as contrarian rather than sycophant: the gap between what this repository's documents assert and what its code does is currently the project's defining characteristic. The PRD claims production-grade engineering with >90% coverage and zero unhandled exceptions. The Covenant asserts cryptographic runtime enforcement and SHA-256 event hashing. The README advertises three enterprise integration adapters.

None of those statements is true today.

That is entirely normal for a project at this stage — **the defect is not the immaturity, it is the documentation asserting maturity it does not have.** Every one of these claims is achievable, and the architecture is good enough to support them. The correct move is to make the documents describe the present accurately and the roadmap ambitiously, then close the gap in the order given above. Doing so converts the largest liability — a governance story with no enforcement — into the strongest differentiator identified in the landscape report.
